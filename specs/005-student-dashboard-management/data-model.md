# Phase 1 Data Model: Student Dashboard & Job Application System

No new tables. Two existing tables gain nullable columns — no removals this time.

## `Company`

| Column | Change | Notes |
|---|---|---|
| `overview` | **added** | `Text`, nullable. The wireframe's about-us-style paragraph. Populated by seeding only in this milestone — no Company profile-editing UI exists yet (see spec.md's Assumptions). |
| *(all other columns)* | unchanged | `company_name`, `industry`, `location`, `hr_contact`, `website`, `logo_path`, `approval_status`, `user_id`, `created_at` — all as Milestones 1/3 left them. |

## `Application`

| Column | Change | Notes |
|---|---|---|
| `interview_mode` | **added** | `String(20)`, nullable. Values in use: `"in_person"` / `"virtual"`. Set by Company via the extended `POST /api/company/applications/<id>/interview` (alongside the existing `interview_datetime`), read by Student here. |
| `company_remark` | **added** | `Text`, nullable. Set by Company via the extended `POST /api/company/applications/<id>/decision` (alongside the existing `status`), read by Student here. Closes the "feedback" gap in Milestone 4's own scope (see spec.md Key Entities). |
| *(all other columns)* | unchanged | `student_id`, `job_position_id`, `application_date`, `status`, `interview_datetime` — unchanged. |

## `Student` / `JobPosition` / `Placement`

Unchanged. `Student.photo_path`/`resume_path` (Milestone 3) now get their first real writes via
this milestone's upload endpoint instead of only seed data. `Placement` (Milestone 1) is read-only
in this milestone — this is the first time anything in the app reads it, but nothing here creates
one.

## Migration

One Flask-Migrate migration, autogenerated and reviewed (constitution Principle II — no manual
SQL): adds `company.overview`, `application.interview_mode`, `application.company_remark`. All
nullable — no default-value complications since nothing is `NOT NULL`.
