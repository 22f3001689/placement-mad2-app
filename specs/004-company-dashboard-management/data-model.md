# Phase 1 Data Model: Company Dashboard & Job/Application Management

No new tables. Two existing tables change — flagged here explicitly since one side is a removal, per
research.md's decision and spec.md's Assumptions.

## `JobPosition` ("Drive")

| Column | Change | Notes |
|---|---|---|
| `drive_name` | **added** | `String(150)`, nullable at the DB level (see Migration below), required by the Create Drive endpoint. The wireframe's separate "Drive Name" field (e.g. "Drive 3"), distinct from `title` ("Job Title", e.g. "Data Scientist"). |
| `eligibility_criteria` | **added** | `Text`, nullable. Freeform replacement for the three columns below. |
| `eligible_branches` | **removed** | Never read anywhere; superseded by `eligibility_criteria`. |
| `min_cgpa` | **removed** | Never read anywhere; superseded by `eligibility_criteria`. |
| `eligible_graduation_year` | **removed** | Never read anywhere; superseded by `eligibility_criteria`. |
| *(all other columns)* | unchanged | `title`, `description`, `salary`, `location`, `skills_required`, `application_deadline`, `status`, `company_id`, `created_at` — all as Milestone 1/3 left them. |

## `Application`

| Column | Change | Notes |
|---|---|---|
| `interview_datetime` | **added** | `DateTime`, nullable. Set independently of `status`; read by Milestone 7's future reminder job. |
| `status` | **meaning extended, same column** | Values in use become `applied` (default, unchanged) / `shortlisted` / `waiting` / `selected` / `rejected`. No migration needed for this — it's a plain string column, same as Milestone 3's `JobPosition.status` change. |
| *(all other columns)* | unchanged | `student_id`, `job_position_id`, `application_date` — unchanged. |

## Migration

One Flask-Migrate migration, autogenerated and reviewed (constitution Principle II — no manual SQL):
adds `job_position.drive_name`, `job_position.eligibility_criteria`, `application.interview_datetime`;
drops `job_position.eligible_branches`, `job_position.min_cgpa`, `job_position.eligible_graduation_year`.

`drive_name` is `nullable=True` at both the migration and the SQLAlchemy model level — adding a `NOT
NULL` column via `ALTER TABLE` to an existing, possibly non-empty SQLite table needs a default value,
which is more migration machinery than this needs. "Required" is enforced the same place username/
password already are for registration: at the API layer (the Create Drive endpoint rejects a missing
`drive_name` with `400`), not a DB constraint. Existing seeded rows get a real value via the updated
`seed_data.py` regardless.
